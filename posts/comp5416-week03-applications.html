COMP5416 W03：应用层与 HTTP（知识点 + 题型）

这一周考什么：HTTP 持久 / 非持久连接要几个 RTT（计算题）；HTTP 状态码（W13 复习课专门列了 200/301/400/404/505）；Web 缓存怎么降低链路利用率和时延；条件 GET 和 304；TCP 和 UDP 各提供什么服务；HTTP/2 怎么缓解队头阻塞；HTTP 和 SMTP、FTP 的对比（推/拉、有无状态、端口）。

期末题型：全是选择题，有单选也有多选，多选题勾错一个会抵消勾对的一个。本周的计算题都是「数 RTT」，概念题都是「下列说法哪些对」。

读法：从上往下读。每节先讲它要解决什么问题，再给结论和算例。

一、应用层的基本概念

1.1 两种应用架构

客户/服务器（Client-Server） P2P
服务器 一直在线，固定 IP，用数据中心扩展 没有一直在线的服务器
端系统之间 客户之间不直接通信 任意两个对等方直接通信
扩展性 靠加服务器 自扩展（self-scalability）：每来一个新用户，既带来新需求，也带来新的上传能力
例子 Web、邮件 BitTorrent

「客户」「服务器」说的是进程的角色：发起通信的进程叫客户进程，等着被联系的叫服务器进程。P2P 里同一个程序下载时是客户，上传时是服务器。

1.2 进程怎么被找到：IP 地址 + 端口号

一台主机上跑着很多进程，光有 IP 地址不够，还要端口号来指明是哪个进程。进程通过 socket（套接字） 收发消息：socket 像一扇门，发送进程把消息推出门，门外怎么送由传输层（TCP 或 UDP）负责。

要背的端口号：

协议 端口
HTTP 80
SMTP 25
DNS 53
FTP 控制 / 数据 21 / 20

1.3 应用对传输服务的四种需求

需求 例子
数据完整性（不能丢） 文件传输、Web、邮件要 100% 可靠；音视频能容忍少量丢失
时延 网络电话、互动游戏要求 100 ms 级
吞吐量 多媒体需要最低吞吐量；文件传输这类「弹性应用」有多少用多少
安全 加密、完整性

注意互动游戏：吞吐量要求很低（几 kbps），但时延要求很严。吞吐量和时延是两回事。存储视频（YouTube）可以缓冲，所以时延要求只有几秒级，比实时视频宽松得多。

1.4 TCP 和 UDP 提供什么

服务 TCP UDP
可靠传输 ✔ ✘
流量控制（不淹没接收方） ✔ ✘
拥塞控制（网络过载时减速） ✔ ✘
面向连接（要先建连接） ✔ ✘
时延保证 ✘ ✘
最低吞吐量保证 ✘ ✘
安全（加密） ✘ ✘

最后三行是陷阱：TCP 和 UDP 都不保证时延、吞吐量和安全。选项里出现「TCP 保证最低吞吐量」一律是错的。

要加密就在 TCP 上面加 SSL/TLS。SSL 属于应用层：应用调用 SSL 库，SSL 库再去用普通的 TCP socket。不要因为它提供「加密的 TCP 连接」就选传输层。

应用 应用层协议 传输层
邮件 SMTP TCP
Web HTTP TCP
文件传输 FTP TCP
流媒体 HTTP（YouTube）、RTP TCP 或 UDP
网络电话 SIP、RTP、Skype 私有协议 TCP 或 UDP

二、HTTP 基础

  • 网页 = 一个基础 HTML 文件 + 若干引用对象（图片、脚本……）。每个对象有自己的 URL，比如 www.someschool.edu/someDept/pic.gif，前半是主机名，后半是路径。
  • HTTP 是客户/服务器模型：浏览器是客户，Web 服务器是服务器；跑在 TCP、端口 80 上。
  • HTTP 是无状态（stateless）的：服务器不记得这个客户之前请求过什么。原因是维护状态很复杂：要保存历史，服务器或客户崩溃后双方的状态可能对不上。
  • 一次交互：客户发起到 80 端口的 TCP 连接 → 服务器接受 → 交换 HTTP 消息 → 关闭 TCP 连接。

三、持久与非持久 HTTP，以及怎么数 RTT

3.1 RTT 和一个对象要多久

RTT（round-trip time）：一个小分组从客户到服务器再回来的时间。

非持久 HTTP 取一个对象：

  1. 1 个 RTT 建 TCP 连接（客户发连接请求，服务器回确认）。
  2. 1 个 RTT 发 HTTP 请求，收到响应的头几个字节。
  3. 再加上把整个文件传完的传输时间。

3.2 两种连接方式

非持久 HTTP 持久 HTTP
一条 TCP 连接 最多传一个对象，传完服务器就关 可以传多个对象，连接保持打开
每个对象 都要重新建连接，2 RTT 第一次建好以后，每个对象只要 1 RTT
缺点 每个对象 2 RTT；每条连接都有操作系统开销 —

浏览器常开多条并行 TCP 连接来加速。

3.3 数 RTT 的通用公式

设页面有 1 个基础 HTML，加 个引用对象，最多 条并行连接，忽略传输时间。基础 HTML 永远要 2 RTT（建连 + 请求），区别在后面 个对象：

方式 引用对象要几个 RTT 总计
非持久，串行（一个一个来） 每个 2 RTT，共
非持久，最多 条并行 分 轮，每轮 2 RTT
持久，最多 条并行 分 轮，每轮 1 RTT
持久 + 流水线（不限并行） 一次全发出去，1 RTT

带你算一遍：1 个 HTML + 10 张图， ：

  • 非持久串行： RTT。
  • 非持久并行：10 张图分 轮，每轮 2 RTT， RTT。
  • 持久并行：2 轮，每轮 1 RTT， RTT。
  • 持久流水线： RTT。

陷阱：持久 HTTP 不要一律答 3 RTT。题目给了「最多 条并行连接」且 时，要分轮数。

加上 DNS：如果浏览器还不知道服务器 IP，要先查 DNS。依次问了几台 DNS 服务器，就把它们的 RTT 全部加在最前面（W05 tutorial 的题型）。

四、HTTP 消息格式与状态码

4.1 请求消息

  • 纯 ASCII，人可以读。每行以 \r\n（回车换行）结尾，单独一个 \r\n 的空行表示首部结束。
  • 方法：
方法 作用 版本
GET 请求一个对象 1.0
POST 把表单内容放在实体体里上传 1.0
HEAD 只要首部，不要对象本身 1.0
PUT 把文件上传到 URL 指定的位置 1.1 新增
DELETE 删除 URL 指定的文件 1.1 新增
  • 表单输入也可以用 GET，放在 URL 里：www.google.com/search?q=new。

4.2 状态码（复习课点名，必背）

状态码在响应消息的第一行（状态行），比如 HTTP/1.1 200 OK。

状态码 意思
200 OK 成功，请求的对象在这条消息后面
301 Moved Permanently 对象永久搬家了，新地址在 Location: 首部里
304 Not Modified 条件 GET 的回答：缓存里的副本还是最新的，不带对象
400 Bad Request 服务器看不懂这条请求
404 Not Found 服务器上没有这个文档
505 HTTP Version Not Supported 不支持这个 HTTP 版本

首位数字是分类：2xx 成功，3xx 重定向，4xx 客户端出错，5xx 服务器出错。分不清 400 和 404 时：400 是「请求本身写错了」，404 是「请求没问题但东西不在」。

五、Cookie：给无状态的 HTTP 加状态

HTTP 本身不记状态，但购物车、登录状态需要记。Cookie 的四个组成部分：

  1. 服务器在响应里加 Set-cookie: 1678 首部。
  2. 浏览器之后每次请求都带 cookie: 1678 首部。
  3. 用户电脑上的 cookie 文件，由浏览器管理。
  4. 网站后端的数据库，用 1678 这个 ID 查这个用户的信息。

流程：第一次访问 → 服务器生成 ID、写数据库、在响应里 Set-cookie → 以后的请求都带这个 ID → 服务器按 ID 做相应操作（购物车、推荐）。

用途：授权、购物车、推荐、会话状态。问题：隐私，网站能借此了解你很多信息。

六、Web 缓存（代理服务器）

6.1 怎么工作

浏览器把所有 HTTP 请求先发给缓存。缓存里有就直接返回；没有就去源服务器取，存一份，再返回给浏览器。

缓存既是客户也是服务器：对浏览器它是服务器，对源服务器它是客户。缓存通常由 ISP（大学、公司）部署。

为什么要缓存：减少响应时间；减少机构接入链路上的流量（最主要的价值）；让资源少的内容提供者也能把内容送出去。

6.2 带你算一遍（讲义例子）

机构局域网 1 Gbps，接入链路 1.54 Mbps，机构路由器到源服务器的 RTT 2 秒。平均对象 100 kbits，浏览器每秒请求 15 个。

  • 浏览器需要的数据率： Mbps。

方案 ① 什么都不做：接入链路利用率 （讲义写 0.99）。利用率接近 1，排队时延爆炸（W02 的流量强度），总时延 = 2 秒 + 好几分钟 + 局域网微秒级。

方案 ② 把接入链路升级到 154 Mbps：利用率 （约 1%），总时延约 2 秒加毫秒级。效果好但贵。

方案 ③ 装一个缓存，命中率 0.4：

  1. 只有没命中的 60% 要走接入链路： Mbps。
  2. 利用率： ，排队时延已经很小（约 0.01 秒）。
  3. 平均时延： 秒。

结论：装缓存比升级链路时延还低，而且便宜。

公式：利用率 ；平均时延 。

6.3 条件 GET：缓存怎么知道自己的副本是不是最新的

缓存发请求时加上首部 If-modified-since: <缓存副本的日期>：

  • 服务器上的对象没改过：回 304 Not Modified，不带对象，省掉传输。
  • 改过：回 200 OK 加上新对象。

计算题型：每次条件 GET 都要发请求问一声，所以每个请求都花 1 个 RTT；只有改过的对象才另外花传输时间。

（ 是没改过的比例。）

七、HTTP/2：缓解队头阻塞

7.1 HTTP/1.1 的问题

HTTP/1.1 允许在一条 TCP 连接上流水线发多个 GET，但服务器按先来先服务（FCFS）的顺序回。一个大对象排在前面，后面的小对象都得等它传完。这就是应用层的队头阻塞（head-of-line blocking, HOL）。另外 TCP 丢了一个段要重传，也会卡住后面所有对象。

量化：请求 1 个大对象 O1（要 100 个时间单位）+ 3 个小对象（各 1 个单位）。

O1 完成 三个小对象完成
HTTP/1.1（FCFS） 100 101、102、103
HTTP/2（分帧交错发） 103 1、2、3

小对象提前了很多，O1 只晚了一点点（讲义原话 "O1 slightly delayed"）。

7.2 HTTP/2 的改进（RFC 7540）

  • 方法、状态码、大部分首部和 1.1 一样。
  • 分帧（framing）：把对象切成帧，交错发送，缓解 HOL 阻塞。帧是二进制编码。
  • 流（stream）：一条 TCP 连接里有多个双向的流，每个流由帧组成。
  • 按客户端指定的优先级发，不必 FCFS。
  • 服务器推送（server push）：客户还没请求，服务器就把它肯定要用的对象（CSS、JS）推过去。

但 HTTP/2 解决不了 TCP 层的队头阻塞：它还是跑在一条 TCP 连接上，TCP 丢一个段，所有流都得等重传。这要到 QUIC 才解决（W12，样卷 Q2 答 TCP）。

八、FTP 和电子邮件（对比题）

W4 课上老师说邮件不会考很细，记住和 HTTP 的对比即可。

8.1 FTP

  • 客户/服务器，控制连接端口 21，数据连接端口 20。
  • 控制和数据分开两条 TCP 连接：命令走控制连接（一直开着），每传一个文件开一条新的数据连接，传完就关。这叫带外（out-of-band）控制。HTTP 的请求和数据在同一条连接上，是带内。
  • FTP 服务器有状态：记得当前目录、是否已认证。HTTP 无状态。

8.2 电子邮件

  • 三个组件：用户代理（Outlook 这种）、邮件服务器（邮箱 + 待发队列）、SMTP（服务器之间传邮件）。
  • SMTP：TCP 端口 25；发件服务器直接连收件服务器；持久连接；消息必须是 7 位 ASCII；用单独一行的 .（CRLF.CRLF）表示消息结束。命令顺序 HELO → MAIL FROM → RCPT TO → DATA → QUIT。
  • 取信用 POP3、IMAP 或 HTTP（网页邮箱），SMTP 只负责送到对方服务器。
    • POP3：下载到本地；「下载并删除」模式换设备就看不到旧邮件；跨会话无状态。
    • IMAP：邮件留在服务器上，可以建文件夹；跨会话有状态。

8.3 对比速查

HTTP SMTP FTP
推 / 拉 pull（拉） push（推） —
有无状态 无状态 — 有状态
控制信息 带内 带内 带外
端口 80 25 21 / 20
多个对象 每个对象一个响应 多个对象放在一条 multipart 消息里 每个文件一条数据连接

考点小结

  1. ★★★ 数 RTT：基础 HTML 2 RTT；非持久每个对象 2 RTT；持久每轮 1 RTT；有并行上限 就分 轮。
  2. ★★★ 状态码 200 / 301 / 304 / 400 / 404 / 505 各是什么意思。
  3. ★★★ TCP vs UDP：两者都不保证时延、吞吐量、安全；SSL 在应用层。
  4. ★★ Web 缓存：利用率 数据率 / 链路速率；缓存比升级链路便宜且更快；缓存既是客户也是服务器。
  5. ★★ 条件 GET：If-modified-since → 304 Not Modified（不带对象）。
  6. ★★ HTTP/2：分帧、流、优先级、服务器推送，缓解应用层 HOL；TCP 层的 HOL 仍在。
  7. ★★ 端口 80 / 25 / 53 / 21 / 20；HTTP 无状态、FTP 有状态；HTTP pull、SMTP push。
  8. ★ Cookie 四个组成部分；PUT、DELETE 是 1.1 才有；POP3 vs IMAP。

题目

格式照期末：选择题，标「（多选）」的可能不止一个对，但勾错会扣掉勾对的分。

Q1（复习课） 服务器回复 301 Moved Permanently 表示什么？ A. 请求成功　B. 对象已永久移动，新位置在 Location 首部　C. 服务器看不懂请求　D. 文档不存在

B。

Q2（复习课） 下列状态码与含义对应正确的是？（多选） A. 200：请求成功，对象在消息中 B. 400：服务器上找不到文档 C. 404：服务器上找不到文档 D. 505：不支持的 HTTP 版本

A、C、D。400 是服务器看不懂请求。

Q3（讲义） 页面含 1 个 HTML 和 10 张图，使用非持久 HTTP、不并行，忽略传输时间，共需多少 RTT？ A. 11　B. 12　C. 20　D. 22

D。 。

Q4（Kurose 交互题型） 同上，但最多 5 条并行 TCP 连接，使用持久 HTTP。共需多少 RTT？ A. 3　B. 4　C. 6　D. 12

B。基础 HTML 2 RTT；10 张图分 2 轮，每轮 1 RTT；共 4。A 是忘了并行上限。

Q5（Kurose 交互题型） 同上，但改用非持久 HTTP（仍最多 5 条并行）。共需多少 RTT？ A. 4　B. 6　C. 12　D. 22

B。 。

Q6（Midterm 练习） RTT = 45 ms，服务器发一个对象要 2 ms。客户依次发 60 个请求，用 If-Modified-Since，其中 70% 的对象没改过。总时间是？ A. 2700 ms　B. 2712 ms　C. 2736 ms　D. 2820 ms

C。 。A 忘了传输时间；D 是把 70% 当成要传的。

Q7（Midterm 练习） 上题中那 70% 没改过的对象，服务器回的状态码是？ A. 200 OK　B. 304 Not Modified　C. 301 Moved Permanently　D. 404 Not Found

B。

Q8（讲义） 接入链路 1.54 Mbps，浏览器总共需要 1.5 Mbps，装了命中率 0.4 的缓存。接入链路利用率约为？ A. 0.97　B. 0.58　C. 0.40　D. 0.01

B。 。A 是没装缓存时的值。

Q9（讲义） 关于 Web 缓存，正确的是？（多选） A. 缓存对浏览器是服务器，对源服务器是客户 B. 缓存能减少机构接入链路上的流量 C. 装缓存一定比升级接入链路更贵 D. 缓存通常由 ISP 部署

A、B、D。C 反了，讲义结论是缓存更便宜。

Q10（讲义） TCP 和 UDP 都不提供的是？（多选） A. 可靠传输　B. 时延保证　C. 最低吞吐量保证　D. 加密

B、C、D。可靠传输 TCP 提供。

Q11（讲义） SSL 位于哪一层？ A. 物理层　B. 网络层　C. 传输层　D. 应用层

D。

Q12（讲义） 关于 HTTP/2，正确的是？（多选） A. 把对象切成帧，交错发送以缓解队头阻塞 B. 改了 HTTP/1.1 的方法和状态码 C. 支持服务器推送 D. 完全消除了 TCP 丢包造成的队头阻塞

A、C。B 错：方法和状态码基本不变。D 错：TCP 层的 HOL 要 QUIC 才解决。

Q13（讲义） 关于 HTTP 和 FTP，正确的是？（多选） A. HTTP 是无状态的 B. FTP 服务器记得用户的当前目录 C. FTP 的控制和数据在同一条 TCP 连接上 D. FTP 数据连接默认端口 20

A、B、D。C 错：FTP 是带外控制，两条连接。

Q14（Midterm 练习） 关于 SMTP 和 HTTP 的推拉性质，正确的是？ A. SMTP pull，HTTP push　B. SMTP push，HTTP pull　C. 都是 push　D. 都是 pull

B。

Q15（Midterm 练习） SMTP 使用的传输层协议和端口是？ A. TCP，25　B. TCP，80　C. UDP，25　D. UDP，53

A。

Q16（讲义） 下列哪个 HTTP 方法是 HTTP/1.1 才新增的？（多选） A. GET　B. HEAD　C. PUT　D. DELETE

C、D。

Q17（讲义） 下列哪些是 cookie 机制的组成部分？（多选） A. 响应消息中的 Set-cookie 首部 B. 请求消息中的 cookie 首部 C. 浏览器管理的 cookie 文件 D. TCP 首部中的会话字段

A、B、C。第四个组成部分是网站后端数据库，TCP 首部里没有会话字段。

Q18（讲义） 一个对象用非持久 HTTP 获取，响应时间是？ A. 1 RTT + 传输时间　B. 2 RTT + 传输时间　C. 3 RTT　D. 只有传输时间

B。建连 1 RTT + 请求响应 1 RTT + 传输时间。
