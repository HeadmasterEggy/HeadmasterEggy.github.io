一、DNS：把名字翻译成 IP 地址

1.1 为什么需要 DNS

机器之间通信用 IP 地址（IPv4 是 32 位），人记的是名字（www.yahoo.com）。DNS（Domain Name System）负责把名字翻译成 IP。它同时是两样东西：

  1. 分布式数据库：数据分散在一个层次结构的很多名字服务器上。
  2. 应用层协议：主机和名字服务器之间按它来问答。DNS 端口 53，主要用 UDP（响应太大或区域传送时用 TCP，所以「用 TCP 还是 UDP」的答案是都用）。

DNS 除了翻译名字，还提供：主机别名（一个真名可以有好几个别名）、邮件服务器别名、负载分配（一个名字对应一组 IP，每次轮换返回顺序，把流量分散到多台服务器）。

1.2 为什么不做成一台集中的服务器

  • 单点故障：它挂了全网都没法解析。
  • 距离远：离它远的用户时延高。
  • 扩展不了：一台机器扛不住全世界的查询。
  • （课本还有一条：维护量太大。）

1.3 层次结构：根 → TLD → 权威

服务器 管什么
根（root） 层次的顶端，知道各个 TLD 服务器在哪。逻辑上 13 个（a 到 m），每个其实是全球很多台镜像
TLD（顶级域） 管 com、org、edu、net 和国家域 uk、au、jp 等，知道每个域的权威服务器在哪
权威（authoritative） 组织自己的 DNS 服务器，存这个组织里主机的权威「名字 → IP」
本地（local） 每个 ISP（大学、公司、家庭宽带）都有一个，也叫默认名字服务器。主机的查询先发给它，由它代为去层次结构里问。它严格来说不属于这个层次结构

查 www.amazon.com 的一级近似：问根 → 得到 com 服务器 → 问 com → 得到 amazon.com 的服务器 → 问它 → 得到 IP。

1.4 迭代查询和递归查询（样卷 Q3）

场景：主机 cis.poly.edu 想要 gaia.cs.umass.edu 的 IP。

迭代查询：被问的服务器只回答「我不知道，你去问某某」，由本地 DNS 一个个去问。

sequenceDiagram
    participant H as 主机
    participant L as 本地 DNS
    participant R as 根
    participant T as TLD (.edu)
    participant A as 权威 dns.cs.umass.edu
    H->>L: ① 问 gaia.cs.umass.edu
    L->>R: ② 问根
    R-->>L: ③ 去问 .edu 的 TLD
    L->>T: ④ 问 TLD
    T-->>L: ⑤ 去问 dns.cs.umass.edu
    L->>A: ⑥ 问权威
    A-->>L: ⑦ A 记录：IP 地址
    L-->>H: ⑧ 返回 IP

递归查询：每一级都替你往下问，答案再一级级传回来：主机 → 本地 → 根 → TLD → 权威，然后 权威 → TLD → 根 → 本地 → 主机。也是 8 条消息，但根和 TLD 要一直参与并等结果，上层负担很重。

迭代 递归

谁跑来跑去 本地 DNS 层次里的每一级
上层负载 低 高
最佳实践 是（样卷 Q3.5） 否

实际常见做法：主机 → 本地 DNS 是递归（主机只要答案），本地 DNS → 层次结构是迭代。

样卷怎么问：① 和 ② 之间本地 DNS 先问谁 → 根；根让它去问谁 → TLD；TLD 没有这个 IP，让它去问谁 → 权威；最后返回的记录类型 → A；哪种是最佳实践 → 迭代。

1.5 缓存和 TTL

  • 任何名字服务器学到一个映射后都会缓存它，过一段时间（TTL）自动删掉。
  • 本地 DNS 常常缓存了 TLD 服务器的地址，所以根服务器很少被访问。
  • 缓存可能过时：主机改了 IP，所有缓存的 TTL 到期前别人可能还拿着旧地址。所以 DNS 是「尽力而为」的翻译。

1.6 四种资源记录（RR）

记录格式：(name, value, type, ttl)。

类型 name value 例子
A 主机名 IP 地址 (gaia.cs.umass.edu, 128.119.245.12, A)
NS 域名 该域权威服务器的主机名 (umass.edu, dns.umass.edu, NS)
CNAME 别名 规范名（真名） (www.ibm.com, servereast.backup2.ibm.com, CNAME)
MX 域名 邮件服务器的名字 (umass.edu, mail.umass.edu, MX)

一句话：A 给 IP；NS 给服务器名；CNAME 给真名；MX 给邮件服务器。

NS 和 A 成对出现：NS 只给了权威服务器的名字，光有名字连不上，所以 TLD 还会同时给一条这个服务器的 A 记录（叫胶水记录）。

例：新公司注册 networkutopia.com，注册商往 .com TLD 插入两条：

公司自己在权威服务器上放 (www.networkutopia.com, 212.212.212.22, A) 之类的记录。所以本地 DNS 问 TLD 时，TLD 会返回 2 条记录（NS + A）。

二、Socket：程序怎么用网络

不考写代码，但会考概念。

  • socket 是应用进程和传输层之间的门。门以上（应用）由开发者控制，门以下（传输层及以下）由操作系统控制。
  • 两种 socket：SOCK_DGRAM = UDP（不可靠数据报），SOCK_STREAM = TCP（可靠字节流）。
UDP socket TCP socket
连接 不用建立，直接发 客户先 connect()，服务器 accept()
目的地址 每个分组都要带目的 IP + 端口（sendto） 建连时给一次，之后 send 不用再给
收数据 recvfrom() 同时拿到数据和发送方地址 recv() 只拿数据
服务器有几个 socket 1 个，所有客户共用 1 个欢迎 socket + 每个客户 1 个连接 socket
可靠性 可能丢、可能乱序 可靠、按序

TCP 服务器的两个 socket：欢迎 socket 一直 listen() 等新客户；每来一个客户，accept() 就新建一个连接 socket 专门和它通信，用完关掉，欢迎 socket 不关。所以 TCP 服务器接了 3 条连接，就有 3 个连接 socket（不算欢迎 socket）。

UDP 服务器用同一个 socket 和所有客户通信：服务器端口 5300、客户乙端口 8200，服务器发给乙的段是（源 5300，目的 8200）。

3.1 问题

3.2 客户/服务器方式

  • ：服务器要亲自发 份，每份 。
  • ：最慢的那个用户下完一份要这么久。
  • 第一项随 线性增长，用户越多越慢，没有上限。

3.3 P2P 方式

  • ：服务器至少发出一份（注意不是 份，剩下的由用户之间互相传）。
  • ：最慢的用户下完一份。
  • ：所有人加起来要收 比特，全系统总上传速率是服务器加所有用户。

四、BitTorrent

  • torrent：交换同一个文件分块的一群用户。tracker：记录谁在这个 torrent 里。文件切成 256 KB 的分块（chunk）。
  • 新用户加入：向 tracker 注册，拿到用户列表，和其中一部分（邻居）连接；一开始一个块都没有，边下边传；用户随时来去（churn）；下完可以走，也可以留下来当种子。

两个策略（必考）：

策略 规则 为什么
请求：rarest first（最稀缺优先） 定期问邻居有哪些块，先要邻居里最少人有的块 稀有块的持有者一走，大家就拼不出完整文件了；先复制稀有块让文件更不容易丢
发送：tit-for-tat（一报还一报） 只给当前给我发得最快的 4 个人发块，其他人被「阻塞（choked）」；每 10 秒重新评估这 4 个人 激励大家多上传
乐观疏通（optimistic unchoke） 每 30 秒随机挑一个人给他发 新来的人还没东西可传，永远进不了别人的前 4 名；随机给一次让他有机会起步，也让自己发现更好的伙伴

结果：上传越快，找到的伙伴越好，下载也越快。

陷阱：10 秒是重新评估前 4 名，30 秒是乐观疏通，别弄反。

五、DHT：分布式哈希表

5.1 是什么

一个分散在很多用户上的 (key, value) 数据库。要解决两件事：这对 (key, value) 存在哪个节点、给定 key 怎么找到那个节点。

5.2 key 归谁：立即后继

  1. 用哈希函数把 key 变成 里的整数，比如 hash("Led Zeppelin IV") = 15。
  2. 每个节点也有一个这个范围里的 ID。
  3. key 存到它的立即后继（immediate successor）上：ID 大于等于 key 的最小那个节点。
  4. 没有比 key 大的节点，就绕回最小的节点（环形）。

例（ ，节点 1、3、4、5、8、10、12、14）：

key 存在 原因
1 1 正好有节点 1
2 3 ≥2 的最小 ID
13 14 ≥13 的最小 ID 是 14（12 数值上更近，但不是后继）
15 1 没有 ≥15 的节点，绕回 1

两个陷阱：「最接近」指后继，不是数值上最近；超出最大 ID 要绕回。

5.3 怎么查：环形 DHT 和捷径

  • 基本版：每个节点只知道自己的后继，查询沿着环一个个传，平均要 条消息。
  • 加捷径（shortcut）：每个节点记后继、前驱、若干捷径（跳到远处的节点）。可以做到每个节点 个邻居、查询 条消息。讲义例子里同一个查询从 6 条降到 2 条。Chord 就是这样一个 DHT。

5.4 节点离开（churn）

  • 每个节点记两个后继，并定期 ping 它们。
  • 立即后继离开了，就把第二个后继升为立即后继，再问它的后继是谁，作为新的第二后继。
  • 例：环 1、3、4、5、8、10、12、15，节点 5 走了。节点 4 发现后，把 8 设为立即后继，问 8 的后继是谁（10），把 10 设为第二后继。
  • 为什么记两个：只记一个的话，后继一走环就断了。

六、本周 Tutorial：用 Wireshark 看 HTTP

这周的 tutorial 练的是 W03 的 HTTP，有两个结论值得记：

  • 条件 GET 实测：清空缓存后第一次 GET 没有 If-Modified-Since，服务器回 200 和文件内容；第二次 GET 带上 If-Modified-Since，服务器回 304 Not Modified，不带内容。
  • HTTP Basic 认证不安全：第一次请求受保护页面，服务器回 401 Authorization Required；浏览器再请求时加 Authorization: Basic d2lyZXNoYXJrLXN0dWRlbnRzOm5ldHdvcms=。这串只是 Base64 编码，解码就是 用户名:密码（wireshark-students:network）。编码不是加密，抓包就能看到密码，所以需要 SSL/TLS。
  • Wireshark 里一个 HTTP 消息套在 TCP 段里，TCP 段套在 IP 数据报里，IP 数据报套在以太网帧里，所以能同时看到 Frame / Ethernet / IP / TCP / HTTP 五层。

考点小结

  1. ★★★ 迭代 DNS 8 步：本地 → 根 → TLD → 权威，最后返回 A 记录；迭代是最佳实践，递归让上层负载重。
  2. ★★★ A / NS / CNAME / MX 的 name 和 value；NS 要配一条 A。
  3. ★★★ 分发时间：C/S ；P2P 。
  4. ★★ 本地 DNS 不属于层次结构；为什么不集中；DNS 缓存和 TTL；DNS 用 UDP（也用 TCP），端口 53。
  5. ★★ BitTorrent：rarest first、tit-for-tat 前 4 名每 10 秒、乐观疏通每 30 秒。
  6. ★★ DHT：后继规则、绕回、 vs 、记两个后继。
  7. ★ Socket：SOCK_DGRAM / SOCK_STREAM；TCP 服务器一个欢迎 socket + 每客户一个连接 socket；UDP 每个分组带地址。
