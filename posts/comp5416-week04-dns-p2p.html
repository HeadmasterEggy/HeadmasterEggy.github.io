一、DNS：把名字翻译成 IP 地址

1.1 为什么需要 DNS

机器之间通信用 IP 地址（IPv4 是 32 位），人记的是名字（www.yahoo.com）。DNS（Domain Name System）负责把名字翻译成 IP。它同时是两样东西：

  1. 分布式数据库：数据分散在一个层次结构的很多名字服务器上。
  2. 应用层协议：主机和名字服务器之间按它来问答。DNS 端口 53，主要用 UDP（响应太大或区域传送时用 TCP，所以「用 TCP 还是 UDP」的答案是都用）。

DNS 除了翻译名字，还提供：主机别名（一个真名可以有好几个别名）、邮件服务器别名、负载分配（一个名字对应一组 IP，每次轮换返回顺序，把流量分散到多台服务器）。

1.2 为什么不做成一台集中的服务器

  • 单点故障：它挂了全网都没法解析。
  • 距离远：离它远的用户时延高。
  • 扩展不了：一台机器扛不住全世界的查询。
  • （课本还有一条：维护量太大。）

1.3 层次结构：根 → TLD → 权威

服务器 管什么
根（root） 层次的顶端，知道各个 TLD 服务器在哪。逻辑上 13 个（a 到 m），每个其实是全球很多台镜像
TLD（顶级域） 管 com、org、edu、net 和国家域 uk、au、jp 等，知道每个域的权威服务器在哪
权威（authoritative） 组织自己的 DNS 服务器，存这个组织里主机的权威「名字 → IP」
本地（local） 每个 ISP（大学、公司、家庭宽带）都有一个，也叫默认名字服务器。主机的查询先发给它，由它代为去层次结构里问。它严格来说不属于这个层次结构

查 www.amazon.com 的一级近似：问根 → 得到 com 服务器 → 问 com → 得到 amazon.com 的服务器 → 问它 → 得到 IP。

1.4 迭代查询和递归查询（样卷 Q3）

场景：主机 cis.poly.edu 想要 gaia.cs.umass.edu 的 IP。

迭代查询：被问的服务器只回答「我不知道，你去问某某」，由本地 DNS 一个个去问。

sequenceDiagram
    participant H as 主机
    participant L as 本地 DNS
    participant R as 根
    participant T as TLD (.edu)
    participant A as 权威 dns.cs.umass.edu
    H->>L: ① 问 gaia.cs.umass.edu
    L->>R: ② 问根
    R-->>L: ③ 去问 .edu 的 TLD
    L->>T: ④ 问 TLD
    T-->>L: ⑤ 去问 dns.cs.umass.edu
    L->>A: ⑥ 问权威
    A-->>L: ⑦ A 记录：IP 地址
    L-->>H: ⑧ 返回 IP

递归查询：每一级都替你往下问，答案再一级级传回来：主机 → 本地 → 根 → TLD → 权威，然后 权威 → TLD → 根 → 本地 → 主机。也是 8 条消息，但根和 TLD 要一直参与并等结果，上层负担很重。

迭代 递归
被问的服务器 指路：「去问它」 跑腿：替你问到底
谁跑来跑去 本地 DNS 层次里的每一级
上层负载 低 高
最佳实践 是（样卷 Q3.5） 否

实际常见做法：主机 → 本地 DNS 是递归（主机只要答案），本地 DNS → 层次结构是迭代。

样卷怎么问：① 和 ② 之间本地 DNS 先问谁 → 根；根让它去问谁 → TLD；TLD 没有这个 IP，让它去问谁 → 权威；最后返回的记录类型 → A；哪种是最佳实践 → 迭代。

1.5 缓存和 TTL

  • 任何名字服务器学到一个映射后都会缓存它，过一段时间（TTL）自动删掉。
  • 本地 DNS 常常缓存了 TLD 服务器的地址，所以根服务器很少被访问。
  • 缓存可能过时：主机改了 IP，所有缓存的 TTL 到期前别人可能还拿着旧地址。所以 DNS 是「尽力而为」的翻译。

1.6 四种资源记录（RR）

记录格式：(name, value, type, ttl)。

类型 name value 例子
A 主机名 IP 地址 (gaia.cs.umass.edu, 128.119.245.12, A)
NS 域名 该域权威服务器的主机名 (umass.edu, dns.umass.edu, NS)
CNAME 别名 规范名（真名） (www.ibm.com, servereast.backup2.ibm.com, CNAME)
MX 域名 邮件服务器的名字 (umass.edu, mail.umass.edu, MX)

一句话：A 给 IP；NS 给服务器名；CNAME 给真名；MX 给邮件服务器。

NS 和 A 成对出现：NS 只给了权威服务器的名字，光有名字连不上，所以 TLD 还会同时给一条这个服务器的 A 记录（叫胶水记录）。

例：新公司注册 networkutopia.com，注册商往 .com TLD 插入两条：

公司自己在权威服务器上放 (www.networkutopia.com, 212.212.212.22, A) 之类的记录。所以本地 DNS 问 TLD 时，TLD 会返回 2 条记录（NS + A）。

二、Socket：程序怎么用网络

不考写代码和语法，只考概念（和 W05 的多路分解是一回事）。

  • socket 是应用进程和传输层之间的门。门以上（应用）由开发者控制，门以下（传输层及以下）由操作系统控制。
  • 两种 socket：UDP socket（不可靠数据报）和 TCP socket（可靠字节流）。
UDP socket TCP socket
连接 不用建立，直接发 先建立连接（三次握手）
目的地址 每个分组都要带目的 IP + 端口 建连时给一次，之后不用再给
服务器有几个 socket 1 个，所有客户共用 1 个欢迎 socket + 每个客户 1 个连接 socket
可靠性 可能丢、可能乱序 可靠、按序

TCP 服务器的两个 socket：欢迎 socket 一直等新客户；每来一个客户，就新建一个连接 socket 专门和它通信，用完关掉，欢迎 socket 不关。所以 TCP 服务器接了 3 条连接，就有 3 个连接 socket（不算欢迎 socket）。

UDP 服务器用同一个 socket 和所有客户通信：服务器端口 5300、客户乙端口 8200，服务器发给乙的段是（源 5300，目的 8200）。

考点小结

  1. ★★★ 迭代 DNS 8 步：本地 → 根 → TLD → 权威，最后返回 A 记录；迭代是最佳实践，递归让上层负载重。
  2. ★★★ A / NS / CNAME / MX 的 name 和 value；NS 要配一条 A。
  3. ★★ 本地 DNS 不属于层次结构；为什么不集中；DNS 缓存和 TTL；DNS 用 UDP（也用 TCP），端口 53。
  4. ★ Socket 概念：TCP 服务器一个欢迎 socket + 每客户一个连接 socket；UDP 一个 socket 服务所有客户、每个分组带地址。

题目

格式照期末：大多是单选；标「（多选）」的可能不止一个对（真题靠题干的复数措辞提示），勾错倒扣，但每题最低 0 分。答题技巧见样卷解析：考试题型与答题技巧。

Q1（样卷 Q3.1） 迭代查询中，本地 DNS 收到主机的查询后（缓存里没有），先去问谁？
A. 用户　B. 本地 DNS　C. 根 DNS　D. TLD DNS　E. 权威 DNS

C。

Q2（样卷 Q3.3） TLD 服务器没有要找的 IP，它让本地 DNS 去问谁？
A. 本地 DNS　B. 根 DNS　C. TLD DNS　D. 权威 DNS

D。

Q3（样卷 Q3.4） 最后返回给用户的是哪种记录？
A. A　B. CNAME　C. NS　D. MX

A。主机名 → IP。

Q4（样卷 Q3.5） 哪种查询被认为是最佳实践？
A. 迭代　B. 递归

A。减轻根和 TLD 的负担。

Q5（讲义） 关于递归查询，正确的是？（多选）
A. 把解析的负担交给被问的服务器
B. 层次结构上层的负载重
C. 被问的服务器只回答「去问谁」
D. 本例中消息数和迭代查询一样是 8 条

A、B、D。C 描述的是迭代。

Q6（讲义） 关于本地 DNS 服务器，正确的是？（多选）
A. 严格来说不属于 DNS 层次结构
B. 也叫默认名字服务器
C. 存有所有域的权威记录
D. 缓存最近的名字到地址映射，可能过时

A、B、D。

Q7（讲义） 记录 (umass.edu, dns.umass.edu, ?) 的类型是？
A. A　B. NS　C. CNAME　D. MX

B。value 是权威服务器的主机名。

Q8（讲义） 记录 (www.ibm.com, servereast.backup2.ibm.com, ?) 的类型是？
A. A　B. NS　C. CNAME　D. MX

C。别名 → 规范名。

Q9（Midterm 练习） TLD 服务器上有 (www.enterprise.com, dns.enterprise.com, NS) 和 (dns.enterprise.com, 146.54.20.201, A)。本地 DNS 问 TLD 时会得到几条记录？
A. 1　B. 2　C. 3　D. 4

B。NS 加上它的 A（胶水记录）。

Q10（Midterm 练习） DNS 使用哪种传输层协议？
A. 只用 TCP　B. 只用 UDP　C. 两者都用　D. 都不用

C。一般查询用 UDP，响应过大或区域传送用 TCP。

Q11（讲义） 为什么 DNS 不用一台集中式服务器？（多选）
A. 单点故障　B. 离远处用户时延高　C. 扩展不了　D. UDP 不支持

A、B、C。

Q12（Midterm 练习） TCP 服务器在欢迎端口 6950 上接受了 3 条连接（来自两台主机）。服务器因此新建了几个 socket（不含欢迎 socket）？
A. 1　B. 2　C. 3　D. 4

C。每条连接一个连接 socket。

Q13（Midterm 练习） UDP 服务器用同一个 socket（端口 5300）和两个客户通信，客户乙的端口是 8200。服务器发给乙的段的（源端口，目的端口）是？
A. (8200, 5300)　B. (5300, 8200)　C. (5300, 5300)　D. (8200, 8200)

B。

Q14（讲义） 关于 socket，正确的是？（多选）
A. TCP socket 提供可靠字节流
B. UDP 客户每次发送都要指明目的 IP 和端口
C. 传输层由应用开发者控制
D. UDP 服务器要为每个客户新建一个 socket

A、B。传输层由操作系统控制；UDP 服务器一个 socket 服务所有客户。

Q15（讲义） 记录 (umass.edu, mail.umass.edu, ?) 的类型是？
A. A　B. NS　C. CNAME　D. MX

D。value 是该域的邮件服务器名。和 Q7 对比：同样是「域名 → 主机名」，NS 指向权威 DNS 服务器，MX 指向邮件服务器。
