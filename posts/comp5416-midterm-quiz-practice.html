Q1 — 答案 C

网络层：把数据报（datagram）从源主机送到目的主机。

官方给的五句话对应关系（每句只对应一层，背下来就是送分题）：

描述 层
「把帧从一个结点经某种介质传到另一个结点」 链路层
「处理来自应用层的段的交付，可靠或不可靠」 传输层
「把数据报从源主机送到目的主机」 网络层
「处理来自各种网络应用的消息」 应用层
「比特在线缆上」 物理层

⚠️ B 的陷阱：传输层管的是段（segment）、进程到进程；网络层管的是数据报、主机到主机。 看到「datagram」和「host to host」就选网络层。

Q7 — 答案 B

SMTP 是 push，HTTP 是 pull。

怎么理解：

协议 方向 谁发起
SMTP 把邮件「推」到对方的邮件服务器上 发送方
HTTP 从服务器「拉」东西下来 接收方（浏览器）

官方图里的三个点：

位置 协议
Alice 的 UA → Alice 的邮件服务器 SMTP
Alice 的邮件服务器 → Bob 的邮件服务器 SMTP

📖 Week 03 讲义

Q11 — 答案 C

Both（两者都用）。

官方原文：DNS 一般用 UDP，但在某些情况（如区域传送 zone transfer）会用 TCP，所以答案是 Both。

场景 协议
普通查询/应答 UDP（报文小、省一个建连 RTT）
区域传送（zone transfer） TCP（数据量大且必须可靠）
应答超过 512 字节 TCP（UDP 被截断后改用 TCP 重试）

⚠️ A 是最常见的错选。 很多题库把 DNS 写成「UDP」—— 但只要选项里出现 Both，本课程的官方答案就是 Both。 只有问「DNS 主要用哪个」时才答 UDP。

📖 Week 04 讲义；Week 05 Tutorial

Q12 — 答案 B

2 条：一条 NS 记录 + 一条 A 记录。

为什么必须成对返回：

  • NS 记录只告诉你权威服务器叫什么名字（dns.enterprise.com）
  • 不知道它的 IP 就联系不上它；若为解析这个名字再发一次查询，会陷入死循环
  • 所以 TLD 把对应的 A 记录一起塞进「附加区（Additional Section）」

这条随行的 A 记录有个正式名称：胶水记录（glue record）。

💡 同样的结构也出现在 MX 上：MX 记录的 value 是邮件服务器的「名字」， 要拿 IP 还得再查一条 A —— 「指名字的记录」永远需要一条 A 兜底。

Q19 — 答案 B

服务器发出的段：源端口 = 自己的 5300，目的端口 = 客户乙的 8200。

UDP 的关键性质：

事实 说明
UDP 套接字只由二元组标识 目的 IP + 目的端口
两个客户发来的段进同一个套接字 因为它们的目的端口都是 5300
服务器靠什么区分客户 靠 recvfrom() 返回的地址，不是靠套接字

发回复时，把「收到的源端口」当作「要发的目的端口」填回去 —— 这就是「源端口号提供了返回地址」的含义。

⚠️ A 把方向搞反了（那是客户乙发给服务器的段）。

📖 Week 05 讲义

Q20 — 答案 C

3 个套接字。

三个四元组互不相同 ⇒ 三个不同的套接字。

⚠️⚠️ 本题与 Q19 是刻意配对的对比题：

UDP（Q19） TCP（Q20）
套接字标识 二元组：目的 IP + 目的端口 四元组：源 IP + 源端口 + 目的 IP + 目的端口
多个客户 → 同一服务器端口 全进同一个套接字 各自独立的套接字
本题结果 1 个套接字 3 个套接字

注意右侧那台客户（IP = C）开了两条连接： 源 IP 相同、目的完全相同，只有源端口不同（5412 vs 6316），照样是两个套接字 —— 这正说明 TCP 用的是四元组而非二元组。

⚠️ A（1 个）就是把 TCP 当成 UDP 来想的结果。 💡 欢迎套接字（welcoming socket）不算在内 —— 它只负责接受连接请求。
