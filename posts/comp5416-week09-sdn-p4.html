COMP5416 Week 09 流媒体 Tutorial 解答

Posted on 2026-11-03 Edited on 2026-11-15 In Course Notes , COMP5416 Word count in article: 4.1k Reading time ≈ 15 mins.
COMP5416 Week 09 流媒体 tutorial（Lab 7 Streaming）完整解答：播放时刻与按时到达的块数、播放时延与缓冲占用、最小播放时延、卡顿周期与缓冲变满的时间。

COMP5416 W09：流媒体播放与卡顿（大白话版）

一句话：网上看视频，数据到得时快时慢，可画面必须匀速播。办法是先攒一点再开播。这周的 tutorial 就是算「攒多久才不卡」「攒多了缓冲里会存几块」「网速不够时播多久卡多久」。

考什么：W09 讲课本身（SDN / SKA 嘉宾讲座）不考。考的是 W9 tutorial 的两道流媒体题，W13 复习课也专门讲了播放时延和缓冲。期末全是选择题（单选 + 多选，多选勾错一个抵掉勾对的一个），可能的考法：

  • 给一张「每块什么时候到」的图，问从某时刻开播有几块按时、缓冲里最多几块、最早什么时候开播才能全部按时；
  • 给 Q、r、x、B，算每次播多久、卡多久、缓冲多久填满。

读法：第一节讲道理（对应 W08 讲义的客户端缓冲），第二、三节逐题讲 tutorial，节末有「怎么做题」。最后是做题速查和 16 道带答案的练习。

一、先把道理讲清楚：为什么要先缓冲再播

1.1 问题在哪

服务器把视频切成一块一块，匀速发出：每隔 Δ 发一块，每块正好够播 Δ 那么长。

可网络时延会变（抖动，jitter）：有的块路上顺，早到；有的块堵了，晚到。客户端收到的节奏就乱了。

画面却必须匀速播放：第 1 块播完立刻接第 2 块，中间不能停。讲义叫这个连续播放约束。

所以矛盾是：到得不匀，播得要匀。

1.2 解决办法：先攒一点（播放时延）

第 1 块到了先别急着播，等一会儿再开播。这段等待叫播放时延（playout delay）。等待期间到的块存进客户端缓冲，开播后就从缓冲里一块一块匀速拿出来播。

打个比方：你接了一根忽大忽小的水管往桶里灌水，桶底有个龙头要匀速出水。一开始就开龙头，水管一变小桶就干了；先攒半桶再开龙头，水管小一阵子也不怕。

讲义的三个结论：

情况 结果
播放时延太小 某块到了该播的时刻还没到，缓冲空了，缓冲下溢（underflow），画面卡住
加大播放时延 下溢更少
代价 用户要等更久才开始看（这就是「初始播放时延的权衡」）

1.3 网速够不够：E(x) 和 r

讲义的模型：缓冲以速率 被填（网速，会变），以速率 被抽走（视频码率，恒定）。

情况 结果
平均填充速率 E(x) < r 进得比出得慢，缓冲迟早被抽干，视频卡住，等缓冲重新攒够再播
E(x) ≥ r 缓冲不会空，前提是初始播放时延够大，能扛住 x(t) 的波动

注意：讲义里的 是缓冲里此刻有多少数据；tutorial 第三节的 是开播前要攒的量（门槛）。两个 Q 不是一回事，别混。讲义递推式和算例在 W08 第三节。

怎么做题

  • 「为什么要客户端缓冲」→ 抵消网络时延的变化（抖动），满足连续播放。
  • 「加大播放时延」→ 下溢更少，但用户等得更久。两个都要选。
  • 「E(x) < r」→ 必然卡；「E(x) ≥ r」→ 不一定不卡，还要初始时延够大。

二、Tutorial Exercise 1：按块播放

2.1 一条公式就够

从时刻 开播第 1 块。之后每块紧接着前一块，间隔 Δ。所以第 k 块的播放时刻是：

第 k 块按时 ⟺ 它的到达时间 ≤ 它的播放时刻。 到晚了就错过（这块播不出来）。

三类问题都从这里出发：

问题 做法
从 开播，几块按时 逐块比较「到达时间」和「 」
缓冲里最多几块 在每个时刻数「已经到了、但还没轮到播」的块
最早什么时候开播才能全部按时 每块算「到达时间 − (k−1)Δ」，取最大的那个（让最拖后腿的那块刚好赶上）

第三行的道理：第 k 块要按时，需要 到达时间，即 到达时间 。每块都要满足，就取最大值。

2.4 Q2：推迟一格，t₁ + Δ 开播？

，每块的播放时刻都往后挪一格：第 k 块在 播。

  • 块 2 在 播，1.7Δ 时已到 ✅；
  • 块 3 在 播，2.3Δ 已到 ✅；块 4、5、6 同理 ✅；

答案：6 块（1–6），只有块 7 迟到。 只多等了一个 Δ，按时的块就从 4 变成 6。

2.5 Q3：Q2 的情形下，缓冲里最多同时存几块？

缓冲里存的是「已经到了、还没轮到播」的块。在每个播放时刻（正要播下一块之前）数一下：

时刻 正要播 缓冲里在等的块 数量
1 1 1
2 2 1
3 3、4（都在 2Δ 到 3Δ 之间到了） 2
4 4、5 2
5 5、6 2
6 6 1

答案：最多 2 块。 推迟开播的另一个代价就在这里：要存的块变多，缓冲得更大（W13 复习课：播放时延决定了需要多大的缓冲）。

2.6 Q4：要让每块都按时，最早什么时候开播？

用 2.1 的方法，每块算「到达时间 − (k−1)Δ」：

块 到达 − (k−1)Δ
1 0
2 1.7Δ − Δ = 0.7Δ
3 2.3Δ − 2Δ = 0.3Δ
4 2.8Δ − 3Δ < 0
5 3.3Δ − 4Δ < 0
6 4.3Δ − 5Δ < 0
7 8.3Δ − 6Δ = 2.3Δ

最大的是块 7，所以开播时刻至少要 左右。按整格 Δ 往后推，就是 ，此时块 7 在 播，8.3Δ 已到 ✅。

另一种想法：Q2 里只有块 7 晚了，它该在 播，实际最晚 前到，差不到 2Δ。从 再往后推 2 格，就是 。

官方答案： 。

怎么做题

  1. 先写出每块的播放时刻 ，和到达时间并排列成表，逐行比大小。
  2. 数缓冲：在每个播放时刻，看「已到、未播」的块。
  3. 求最早开播：每块算「到达 − (k−1)Δ」取最大值；题目按整格 Δ 问时就往上取整。
  4. 规律：开播越晚，按时的块越多，缓冲里同时存的块也可能越多；网络送数据的速度不会因此改变。

三、Tutorial Exercise 2：HTTP 流的卡顿

3.1 模型和符号

把缓冲想成一个水池：

符号 意思 水池比喻
客户端缓冲的总容量（bit） 池子最多装多少水
开播前要先攒的量（bit），是起播门槛，不是容量 水攒到这条线才开龙头
视频消耗速率（bps），即码率 龙头出水速度
服务器发送速率（bps），恒定；缓冲没满就一直发 水管进水速度

播放的时候，水池里的水净变化速度 = 进 − 出 = ：

  • ：进得比出得慢，水池一直在减少，迟早干掉 → 卡顿；
  • ：进得比出得快，水池一直在增加，迟早装满。

不播的时候（开播前、卡顿时），只进不出，水池以 的速度涨。

3.2 Q1：x < r 时，每次播多久、卡多久？

过程是一个循环：

  1. 攒水：水池从 0 涨到 ，开始播放；
  2. 播放：水池从 开始，以 的速度减少，减到 0 就卡住。用时 ；
  3. 卡顿：水池从 0 以 的速度重新涨到 ，再开播。用时 ；
  4. 回到第 2 步，如此反复。

带你算一遍： Mb， Mbps， Mbps。

  • 播放： 2 s
  • 卡顿： 0.67 s
  • 一个周期 2.67 s，播放占 2 / 2.67 = 75%

一个漂亮的结论：播放时间占比

和 无关。道理：长期看，每秒只送来 bit，而播 1 秒要 bit，所以只够播 的时间。 调大，只会让每次播得更久、每次也卡得更久（「卡得少但一卡就卡很久」），比例不变。上面的例子 1.5 / 2 = 75%，对得上。

3.3 Q2：x > r、缓冲一开始是空的，什么时候填满？

分两段：

  1. 攒到门槛：从 0 涨到 ，只进不出，用时 ；
  2. 边播边涨：开播后净速度 ，还要再装 ，用时 。

带你算一遍： Mb， Mb， Mbps， Mbps。

  • 攒到 ： s
  • 再装 3 Mb，净速度 1 Mbps：3 s
  • s

填满以后：服务器只在「缓冲没满」时才发，于是它实际上只能跟着播放的速度补，实际发送速率降到 。

怎么做题

  • 先判断 x 和 r 谁大：x < r 用「播放 / 卡顿」公式；x > r 用「填满时间」公式。
  • 播放时长分母是 r − x（净减少速度），卡顿时长分母是 x（只进不出）。最常见的错是把两个分母弄反。
  • 填满时间要分两段：第一段只进不出（÷ x），第二段边播边涨（÷ (x − r)），第二段要装的是 B − Q，不是 B。
  • 问 Q 变化的影响：每次播放、每次卡顿都按比例变，播放占比 x / r 不变。
  • 单位统一：Mb 配 Mbps，结果是秒。

做题速查

  1. ★★★ 第 k 块播放时刻 = 开播时刻 + (k−1)Δ；按时 ⟺ 到达 ≤ 播放时刻。
  2. ★★★ 最早开播时刻 = max（到达时间 − (k−1)Δ）；按整格问就往上取整。Tutorial 答案：t₁ 开播 4 块按时；t₁+Δ 开播 6 块；缓冲最多 2 块；全部按时要 t₁+3Δ。
  3. ★★ 缓冲里的块 = 已到达、还没播的块；开播越晚，存的可能越多。
  4. ★★★ x < r：播放 ，卡顿 ，播放占比 ，与 Q 无关。
  5. ★★ x > r：填满时间 ；填满后实际发送速率降到 r。
  6. ★★ 讲义结论：加大播放时延 → 下溢少、但要等更久；E(x) < r 必卡；E(x) ≥ r 还需要初始时延够大。
  7. ★ tutorial 的 Q 是起播门槛，B 是容量；讲义的 Q(t) 是缓冲当前存量，三者别混。

Q6（自拟） Δ = 1 s，以第 1 块到达为 0 时刻，块 1–5 的到达时间分别是 0、0.5、2.5、3.2、3.5 s。块 1 一到就开播，几块按时？
A. 2　B. 3　C. 4　D. 5

B。播放时刻 0、1、2、3、4：块 1、2、5 按时；块 3（2.5 > 2）、块 4（3.2 > 3）迟到。

Q7（自拟） 同上，要让 5 块全部按时，最早什么时候开播？
A. 0.2 s　B. 0.5 s　C. 1 s　D. 2.5 s

B。到达 − (k−1)Δ：0、−0.5、0.5、0.2、−0.5，最大是 0.5（块 3）。

Q8（讲义） 关于加大客户端的初始播放时延，正确的是？（多选）
A. 能减少缓冲下溢
B. 用户要等更久才开始看
C. 缓冲里同时等待的块可能更多
D. 能提高网络送数据的平均速率

A、B、C。网络送数据的速率不会因为开播晚而变。

Q9（讲义） 平均填充速率 E(x) 小于视频播放速率 r 时，会怎样？
A. 只要初始播放时延够大就不会卡
B. 缓冲迟早被抽空，视频卡住直到缓冲重新攒够
C. 缓冲迟早溢出
D. 播放速率自动降到 E(x)

B。进得比出得慢，再大的初始缓冲也有用完的时候。

Q10（讲义） 客户端缓冲主要是为了应对什么？
A. 视频编码码率太高
B. 网络时延的变化（抖动）
C. 服务器发送速率恒定
D. 视频帧太大

B。到得不匀、播得要匀，中间靠缓冲调节。

Q11（Tutorial） HTTP 流，Q = 1 Mb，r = 2 Mbps，x = 1.5 Mbps。每次连续播放多久？
A. 0.5 s　B. 0.67 s　C. 2 s　D. 4 s

C。Q / (r − x) = 1 / 0.5。

Q12（Tutorial） 同上，每次卡顿多久？
A. 0.5 s　B. 0.67 s　C. 1 s　D. 2 s

B。Q / x = 1 / 1.5。

Q13（自拟） HTTP 流，Q = 2 Mb，r = 4 Mbps，x = 3 Mbps。每次播放时长和卡顿时长分别是？
A. 2 s，0.67 s　B. 0.67 s，2 s　C. 0.5 s，0.67 s　D. 2 s，0.5 s

A。播放 2 / (4 − 3) = 2 s；卡顿 2 / 3 ≈ 0.67 s。播放占比 3/4。

Q14（自拟） x < r 时，把起播门槛 Q 加倍，会怎样？（多选）
A. 每次连续播放时间加倍
B. 每次卡顿时间加倍
C. 播放时间占总时间的比例不变
D. 卡顿不再发生

A、B、C。比例是 x / r，与 Q 无关；只要 x < r 就一定会卡。

Q15（Tutorial） HTTP 流，B = 4 Mb，Q = 1 Mb，x = 3 Mbps，r = 2 Mbps，缓冲初始为空。缓冲什么时候填满？
A. 1.33 s　B. 2 s　C. 3.33 s　D. 4 s

C。1/3 + (4 − 1)/(3 − 2) = 0.33 + 3。

Q16（自拟） HTTP 流，B = 10 Mb，Q = 2 Mb，x = 5 Mbps，r = 3 Mbps，缓冲初始为空。缓冲什么时候填满？填满后服务器实际以多大速率发送？
A. 4.4 s，3 Mbps
B. 4 s，5 Mbps
C. 5 s，3 Mbps
D. 4.4 s，5 Mbps

A。2/5 + 8/2 = 0.4 + 4 = 4.4 s；填满后只能跟着播放补，速率降到 r = 3 Mbps。
