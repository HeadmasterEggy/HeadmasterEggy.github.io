COMP5416 W05：传输层与可靠数据传输（知识点 + 题型）

这一周考什么：UDP 和 TCP 的多路分解（二元组 vs 四元组）；为什么要有 UDP；Internet 校验和手算；rdt 1.0 到 3.0 每一版加了什么；停等协议的利用率；Go-Back-N 和 Selective Repeat 的区别（W13 复习课专门用 N=4、pkt2 丢失的例子对比了两者）。

期末题型：全是选择题，有单选也有多选，多选题勾错一个会抵消勾对的一个。计算题有利用率和校验和；GBN / SR 常考「丢了某个包，发送方要重传几个、接收方怎么回 ACK」。

读法：从上往下读。每节先讲它要解决什么问题，再给结论和算例。

一、传输层干什么

  • 传输层在不同主机上的进程之间提供逻辑通信：应用进程感觉自己直接连着对方进程，不用管中间隔了多少路由器。
  • 传输层协议只跑在端系统上，路由器不管传输层。
  • 发送方把应用消息切成段（segment）交给网络层；接收方把段重组成消息交给应用。
  • 网络层 vs 传输层：网络层是主机到主机（把数据送到那台机器），尽力而为、不可靠；传输层是进程到进程（把数据交给那台机器上的那个程序），在网络层之上增强服务。
  • 互联网两个传输协议：TCP（可靠、按序、拥塞控制、流量控制、要建连接）和 UDP（不可靠、无序，「尽力而为」IP 的简单扩展）。两者都不保证时延和带宽。
层 数据单元
应用层 message（报文）
传输层 segment（段）
网络层 datagram（数据报）
链路层 frame（帧）

二、多路复用与多路分解

2.1 是什么

一台主机上很多进程同时在用网络。

  • 多路复用（发送方）：把来自多个 socket 的数据收集起来，加上传输层首部（里面有源端口、目的端口），交给网络层。
  • 多路分解（接收方）：用首部里的信息把收到的段交给正确的 socket。

每个 IP 数据报带着源 IP、目的 IP；里面装的段带着源端口、目的端口（各 16 位）。主机用这几个值决定交给哪个 socket。

2.2 UDP：只看目的 IP + 目的端口（二元组）

  • UDP socket 由 (目的 IP, 目的端口) 标识。
  • 收到 UDP 段，只看目的端口，交给拥有这个端口的 socket。
  • 所以来自不同源 IP 或不同源端口、但目的端口相同的段，进的是同一个 socket。服务器想知道是谁发的，要自己看收到的段里的源地址；回复时把收到的源端口当成目的端口填回去。

例：服务器端口 6428；客户 1 端口 9157，客户 2 端口 5775。两个客户发来的段目的端口都是 6428，进同一个 socket；服务器回客户 1 的段是（源 6428，目的 9157）。

2.3 TCP：四元组

  • TCP socket 由 (源 IP, 源端口, 目的 IP, 目的端口) 四个值一起标识，接收方四个都用。
  • 所以服务器能同时有很多 TCP socket，每条连接一个。Web 服务器给每个客户一个 socket；非持久 HTTP 每个请求都新开一个 socket。

例：三个段都发往 (B, 80)：

段 源 IP, 源端口 进哪个 socket
① A, 9157 socket 1
② C, 5775 socket 2
③ C, 9157 socket 3

②和③源 IP 一样、目的一样，只有源端口不同，也进不同的 socket。这就是四元组。

UDP TCP
socket 怎么标识 二元组：目的 IP + 目的端口 四元组：源 IP + 源端口 + 目的 IP + 目的端口
不同来源、同一目的端口的段 进同一个 socket 进不同的 socket

三、UDP

3.1 特点

  • 「无修饰（no frills）」：段可能丢失，也可能乱序交给应用。
  • 无连接：发之前不握手，每个段独立处理。

3.2 为什么还要有 UDP（四个理由，必背）

  1. 不用建连接：建连接要多花时延（TCP 三次握手）。
  2. 简单：收发双方都不维护连接状态。
  3. 首部小：只有 8 字节（TCP 至少 20 字节）。
  4. 没有拥塞控制：想发多快就发多快。

用途：流媒体（容忍丢包、在乎速率）、DNS。想在 UDP 上要可靠传输，就在应用层自己做（QUIC 就是这样，W12）。

3.3 UDP 段格式

字段 位数
源端口 16
目的端口 16
length（整个段的字节数，含首部） 16
checksum 16

4 个字段各 2 字节，首部共 8 字节；length 最小是 8。

四、Internet 校验和：检测比特错误

4.1 怎么算

发送方：

  1. 把段的内容（含首部）看成一串 16 位整数。
  2. 全部加起来。最高位产生的进位要加回到最低位（回卷，wraparound）。
  3. 把和按位取反（0 变 1、1 变 0），得到校验和，放进 checksum 字段。

接收方：把所有 16 位整数连同校验和一起加（同样回卷）。结果应该是全 1；再取反就是全 0。不是的话就检测到错误。

4.3 局限

校验和只能检测、不能纠正错误，而且检测不出所有错误：比如两个比特同时翻转、刚好互相抵消，和不变。

五、可靠数据传输（rdt）：一步步搭出来

问题：网络层（IP）不可靠，会翻转比特、丢包。怎么在它上面做出可靠的传输？讲义从最简单的假设开始，每一版只解决上一版的一个新问题。

版本 信道会出什么问题 加了什么
rdt 1.0 什么问题都没有 什么都不用加，直接发
rdt 2.0 比特可能翻转 校验和检测错误 + 接收方反馈 ACK（收到了、没错）/ NAK（有错）+ 收到 NAK 就重传
rdt 2.1 同上，而且 ACK/NAK 本身也可能坏 给分组加序号（0 和 1 两个就够）
rdt 2.2 同上 不用 NAK，只用带序号的 ACK
rdt 3.0 还会丢包（数据、ACK 都会丢） 倒计时定时器，超时就重传

5.1 rdt 2.0 → 2.1：反馈坏了怎么办

rdt 2.0 的问题：接收方回的 ACK/NAK 坏了，发送方不知道对方收没收到。直接重传又可能让接收方收到重复的分组。

rdt 2.1 的办法：反馈坏了就重传；每个分组带序号，接收方看到序号和上一个一样，就知道是重复的，丢掉不交给上层，但仍然回 ACK。

为什么 0 和 1 两个序号就够：这是停等（stop-and-wait）协议，发一个、等回应，同一时刻只有一个分组在路上，只需区分「新的」和「上一个的重复」。

5.2 rdt 2.2：不用 NAK

接收方不发 NAK，而是对最后一个正确收到的分组发 ACK，并带上序号。发送方在等 ACK0 却收到 ACK1，就知道 pkt0 没收好，相当于 NAK，重传 pkt0。这就是重复 ACK 的来源，TCP 的快速重传（W06）就用它。

5.3 rdt 3.0：丢包怎么办

分组整个丢了，接收方根本不知道有这个分组，不会发任何反馈，发送方会一直等。

办法：发送方发完就启动定时器，等「合理的时间」；超时还没收到 ACK 就重传。分组只是慢了没丢的话，重传会造成重复，序号已经能处理。

讲义的四种情况：

情况 发生了什么 结果
(a) 正常 一来一回 不重传
(b) 数据丢了 pkt1 丢失 超时，重传 pkt1
(c) ACK 丢了 pkt1 到了，ack1 丢了 超时重传 pkt1；接收方发现重复，丢掉，再回 ack1
(d) 过早超时 ack1 只是来晚了 重传 pkt1；发送方会收到两个 ack1，第二个忽略

七、Go-Back-N vs Selective Repeat（复习课重点）

两种流水线协议，发送方都最多 个未确认分组在路上，区别在接收方怎么回 ACK、发送方怎么重传。

Go-Back-N（GBN） Selective Repeat（SR）
接收方 ACK 累积 ACK：ACK(n) 表示 n 及以前的全收到了；有空洞时不确认后面的 每个分组单独 ACK
接收方收到乱序分组 丢掉，不缓存；再发一次「最后一个按序收到的」ACK 缓存，并回这个分组自己的 ACK
定时器 只有一个，给最老的未确认分组 每个未确认分组一个
超时后重传 重传这个分组以及它后面所有已发出的分组 只重传超时的那一个
复杂度 接收方简单（只记下一个期待的序号） 接收方要维护窗口和缓存
带宽 浪费（丢一个重传一批） 省

7.1 GBN 走一遍（N = 4，pkt2 丢了）

  1. 发送方发 pkt0、1、2、3，窗口满。
  2. 接收方收 pkt0 回 ack0，收 pkt1 回 ack1。pkt2 丢了。
  3. 发送方收到 ack0 发 pkt4，收到 ack1 发 pkt5。
  4. 接收方收到 pkt3、pkt4、pkt5，都不是它要的 pkt2，全部丢掉，每次都重发 ack1。发送方忽略重复的 ack1。
  5. pkt2 超时，发送方重传 pkt2、3、4、5 四个。
  6. 接收方依次收下并交付，回 ack2、3、4、5。

7.2 SR 走一遍（同样 N = 4，pkt2 丢了）

1–3 同上。

  1. 接收方收到 pkt3、4、5，缓存起来，分别回 ack3、ack4、ack5。发送方记下这三个已确认。
  2. pkt2 超时，发送方只重传 pkt2。
  3. 接收方收到 pkt2，一次性把 pkt2、3、4、5 按序交给上层，回 ack2。
  4. 复习课的问题「ack2 到了会怎样」：发送方窗口的最左端直接滑到 6（3、4、5 早就确认了），可以发新的分组。

一句话：同样丢 pkt2，GBN 重传 4 个，SR 只重传 1 个。GBN 重传数 = 从丢的那个起，窗口里已经发出去的个数。

7.3 SR 接收方的一个细节

收到序号在 [rcvbase − N, rcvbase − 1] 的分组（之前已经交付过的），还是要回 ACK。因为这说明发送方没收到之前的 ACK，不再回一次的话，发送方窗口永远动不了。

7.4 序号空间至少要多大

协议 至少几个序号
停等 2
GBN（窗口 N） N + 1
SR（窗口 N） 2N

SR 要 2N：序号太少的话，接收方分不清收到的是新分组还是上一轮的重传。

反过来问「序号空间有 个序号，窗口 最大多少」（W8 Tutorial 就这么问，复习课让重做）：SR 要 ，严格说 GBN 只要 。例：序号字段 3 比特， ，SR 窗口最多 4，GBN 最多 7。注意 W8 Tutorial 官方答案对 GBN 也按 给分，题目没写明协议时按 答最安全。原题见W06 第十二节。

7.5 和 TCP 的关系

TCP 用累积 ACK、只有一个重传定时器（像 GBN），但接收方通常缓存乱序段、超时只重传一个段（像 SR）。所以 TCP 是两者的混合（W06）。

考点小结

  1. ★★★ GBN vs SR：累积 / 单独 ACK、丢弃 / 缓存、一个 / 每包一个定时器、重传全部 / 只重传一个；会走 N=4、pkt2 丢失的例子。
  2. ★★★ 停等利用率 ；流水线乘 。
  3. ★★★ UDP 二元组、TCP 四元组。
  4. ★★ 为什么要 UDP：不建连接、无状态、首部 8 字节、无拥塞控制。
  5. ★★ 校验和：16 位相加、回卷、取反；接收方加上校验和得全 1。
  6. ★★ rdt 演进：2.0 校验和 + ACK/NAK；2.1 序号；2.2 无 NAK；3.0 定时器。
  7. ★★★ 窗口与序号空间：SR （GBN 严格说 ，但 W8 Tutorial 官方答案也按 ）。
  8. ★ 传输层 vs 网络层：进程到进程 vs 主机到主机；TCP、UDP 都不保证时延和带宽。

Q14（复习课） GBN，窗口 N = 4，发送方发了 pkt0–pkt5，pkt2 丢失，其他都到达。接收方收到 pkt3、4、5 时会？

Q15（复习课） 同上，pkt2 超时后 GBN 发送方重传哪些分组？

Q17（讲义） 关于 GBN 和 SR，正确的是？（多选）

Q20（W8 Tutorial 题型） Selective Repeat，序号字段 3 比特（序号 0–7）。为了不把重传的旧分组当成新分组，发送窗口最大是？
